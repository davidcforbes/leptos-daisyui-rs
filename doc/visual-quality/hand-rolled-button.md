# Hand-rolled button

**Status:** automated (component-drift, since 2026-08-08)
**Seen in:** office-perf-web; reproduced synthetically in this repo's own
negative-control test.

## What it looks like

A raw `<button>` (or a `<div onclick>`) styled inline to look approximately
like a button — right-ish color, right-ish padding — sitting next to real
`Button` components on the same screen. It usually passes a casual glance.
What it's missing only shows up when you interact with it: no hover/active
state transition, no visible focus ring, no theme awareness (it stays the
same color across a light/dark toggle that repaints every real button), and
often no keyboard activation at all.

## Root cause

Someone needed "a clickable thing" and reached for a bare element with
inline classes instead of `Button` (`src/components/button/`). Every state
`Button` gets for free — focus-visible ring, disabled styling, daisyUI's
`btn` color/size/shape variants, theme-driven colors via CSS custom
properties — has to be hand-reimplemented, and in practice never fully is.

## How to check (manual)

Tab through the page; a hand-rolled button either has no visible focus
indicator or a browser-default one that doesn't match the design system.
Toggle the theme switcher and watch it — real buttons repaint, hand-rolled
ones often don't.

## Automation

The daisyUI component-drift sweep (`audit/src/drift.js`, generated by
`audit/src/drift.rs`, `pub fn drift_js`) runs a rule named
`button-without-btn`: any raw `<button>` element under the mount subtree
lacking the `.btn` class is flagged with detail `button-without-btn: raw
button lacks .btn`. `ldui_audit::audit_page` merges this into the same
`AuditReport` as the engine's sweep under `family::COMPONENT_DRIFT`
(`audit/src/page.rs`). This is the third of the three injected violations in
`sweep_detects_injected_style_and_drift_violations`
(`tests/style_audit_smoke.rs`) — a classless `<button id="ldui-audit-inject">`
is injected and the suite asserts both the component-drift count rises *and*
that the `button-without-btn` rule specifically fired (not merely some other
drift rule). Caught by `cargo xtask test-style`.
