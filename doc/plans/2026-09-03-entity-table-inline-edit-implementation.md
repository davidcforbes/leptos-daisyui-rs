# EntityTable Inline Editing Completion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish `ldui-ff2f` so `EntityTable` supports exclusive draft creation and existing-row editing in its existing action column, defers all input refreshes until the edit is saved or discarded, and remains complete and accessible at wide and compact widths.

**Architecture:** Keep the committed `EntityEditState<T>` reducer as the single source of truth for draft and existing-row sessions. Add one generic accepted/pending snapshot gate beside it, mark exactly one existing `EntityColumn::action` as the inline-edit host, and render the one live working row as an overlay over a frozen accepted table snapshot. All other rows and table chrome become genuinely inert until the reducer returns to `Idle`, at which point the latest pending coherent snapshot is published before controls are re-enabled.

**Tech Stack:** Rust 2024, Leptos 0.8 CSR, daisyUI 5/Tailwind, `chromiumoxide`, PixelProof Web, axe-core, the existing `cargo xtask` browser runner, and Beads (`bd`).

- [ ] **Step 3: Implement the smallest render-free gate**

Add this crate-private type below `EntityEditDisposition` in `draft_edit.rs`:

```rust
#[derive(Clone, Debug, PartialEq, Eq)]
pub(crate) struct EntityEditSnapshotGate<S> {
    accepted: S,
    pending: Option<S>,
}

impl<S> EntityEditSnapshotGate<S> {
    pub(crate) const fn new(accepted: S) -> Self {
        Self {
            accepted,
            pending: None,
        }
    }

    pub(crate) const fn accepted(&self) -> &S {
        &self.accepted
    }

    #[cfg(test)]
    pub(crate) const fn pending(&self) -> Option<&S> {
        self.pending.as_ref()
    }

    pub(crate) fn observe(&mut self, next: S, editing: bool) {
        if editing {
            self.pending = Some(next);
        } else {
            self.accepted = next;
            self.pending = None;
        }
    }

    pub(crate) fn release(&mut self) -> bool {
        let Some(pending) = self.pending.take() else {
            return false;
        };
        self.accepted = pending;
        true
    }
}
```

Keep this type crate-private; it is component machinery, not consumer API.

Create one `release_snapshot_before_idle` closure that first observes the current raw envelope as editing, then calls `gate.release()`. Invoke it before `state.cancel()` and before resolving `EntityEditOutcome::Accepted`. Do not invoke it for `Rejected` or a stale resolution. This ordering makes the new snapshot visible before the table reports `Idle` and re-enables controls, including when the consumer updates input signals synchronously in the same callback that accepts the commit.

Mint the public `resolve` callback inside `commit_draft` with that commit's `sequence()` captured. Before releasing a snapshot or resolving state, compare the captured sequence with `pending_commit.sequence()`. A stale callback must return without touching either state. This fixes the current shared-callback shape, which otherwise reads whichever commit happens to be pending and can let an old consumer response resolve a newer attempt despite the reducer's sequence guard.

Use this callback shape; it captures only the `u64` sequence and arena handles, not `T`:

```rust
let sequence = commit.sequence();
let resolve = Callback::new(move |outcome: EntityEditOutcome| {
    let current = pending_commit.with_value(Clone::clone);
    let Some(current) = current.filter(|current| current.sequence() == sequence) else {
        return;
    };
    if matches!(&outcome, EntityEditOutcome::Accepted) {
        release_snapshot_before_idle.run(());
    }
    let disposition = edit_state
        .try_update(|state| state.resolve(&current, outcome))
        .unwrap_or(EntityEditDisposition::IgnoredStale);
    if disposition == EntityEditDisposition::Applied {
        pending_commit.set_value(None);
    }
});
```

Pass this freshly minted `resolve` in `EntityDraftCommit`; delete the one shared `resolve_commit` callback.
