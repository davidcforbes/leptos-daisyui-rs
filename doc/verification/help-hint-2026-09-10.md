## Test-first evidence

The initial compile-only RED established that the new public module did not
exist. A minimal state scaffold then produced the behavioral RED:

```text
cargo test -p leptos-daisyui-rs --lib --features test-mode help_hint
test result: FAILED. 1 passed; 5 failed
```

The failures were the intended behavior assertions for transient hover/focus,
pointer pin persistence, keyboard-pin blur, second activation, and the derived
description ID. After the minimal state implementation the same command passed
6/6. A second RED isolated the multiple-instance stack regression:

```text
cargo test -p leptos-daisyui-rs --lib --features test-mode hidden_or_unmounted_active_hint_reveals_previous_visible_hint
test result: FAILED. 0 passed; 1 failed
```

The final focused state run passed:

```text
cargo test -p leptos-daisyui-rs --lib --features test-mode help_hint
test result: ok. 7 passed; 0 failed
```

The initial browser run failed all three grouped journeys and exposed fixture
and harness defects: an offscreen-pointer setup error, the CDP wrapper dropping
the required empty `touchPoints`, and subject activation being intercepted by
an intentionally pinned screenshot state. These are not claimed as product
mutation controls; the behavioral RED evidence is the native state and stack
tests above. Review of the rendered state additionally found DaisyUI's blank
`::before` chrome, its 8 px tooltip dead gap, and centered clipping at the
pane's left edge. The final oracle scrolls before real input, preserves an
explicit empty touch array, checks both pseudo elements, crosses the real
trigger-to-description boundary, and checks rendered bounds.
